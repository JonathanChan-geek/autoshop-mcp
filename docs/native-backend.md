# 原生后端

调用链为 MCP / CLI → Python 工程副本管理 → 独立 x86 host → 本机原厂 DLL。

host 调用原厂内部 C++ 接口，通过 message-only window 接收进度和诊断，并等待实际编译线程结束。这个隐藏消息接收窗口不是 AutoShop 主界面，不进行桌面操作。x86 host 可以由 64 位 Python 启动。

## 适配范围

当前只支持 profile.json 中固定指纹的 Global.dll、Converter.dll、Parser.dll、device/H3U.dll 和 mfc90.dll。Python 检查文件指纹，host.cpp / profile.h 再进行原生检查。内部 ABI 包含序号导出和固定偏移，更新原厂软件可能破坏兼容性。

支持 H3U 未保护的 IL / LD 块。Python 在调用 host 前拒绝受保护工程、未知机型和未支持的块类型。host 是内部组件，应通过 Python 工具调用。

## 成功条件

编译从新的临时目录开始，不复用原工程 Compile 缓存。每轮删除 Output.prg，检查所有登记程序块的中间文件覆盖率，直到连续两轮机器码一致。仍需同时满足原厂完成消息、无错误诊断、产物非空、源码与非派生配置字节不变。步骤数或返回码本身不构成成功证明。

错误、超时、配置被改写或产物不稳定时，保留日志和报告，不发布工程副本或 ZIP。编译器正常返回警告时会保留警告。配置比较以代码中显式列出的派生文件排除规则为准，不把任意未知文件当成缓存删除。

LD 转换先编译基准，再在新副本中更新对应 HCP 文件条目并替换程序块，最后重新编译。只有机器码与基准一致才交付。此流程证明转换前后编译结果一致，不证明修改后的控制逻辑满足机械要求。

## 已知限制

- 使用私有 ABI，不是官方开放 API。适配不能只改版本字符串或哈希。
- 原厂接口使用 ANSI / GBK；临时目录所在路径应能被系统代码页表示。遇到路径编码问题可把 TEMP 和 TMP 指向可写的 ASCII 目录。
- 工程必须完整，包括通信和轴等配置；不从缺失文件推测配置。
- 原生进程会加载原厂组件，仅使用可信安装和工程。
- 本工具不操作在线 PLC，也不复现机械、伺服或现场总线的实际运行。
