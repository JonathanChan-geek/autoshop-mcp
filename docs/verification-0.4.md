# 0.4 原厂接口验证记录

日期：2026-09-20。范围为仓库 `profile.json` 固定指纹的 H3U 运行库。测试在工程副本和独立 x86 进程内进行，不操作现场 PLC。私有工程、原厂 DLL、完整运行日志不随公开仓库发布。

## IL 转梯形图：已接入，有明确拒绝边界

`CreateConverter` 的转换类型 1 可以生成真正的 LD。0.3 的探针把工作目录设在安装目录，部分输出落到了安装目录；只检查工程副本导致漏检，因此“未找到路径”的旧结论错误。0.4 在加载原厂 DLL 和创建工厂之前就固定工作目录，并同步指定子进程 cwd。

验收链：原工程清缓存编译 → IL 转 LD → HCP 改指新 LD → 删除副本旧 IL → LD 转回 IL → 新 LD 原厂初始化编译 → 再次转回 IL → 完整清缓存编译 → 机器码逐字节对比。

初次编译会整理新 LD 文件的内部数据。仅允许目标 LD 发生这次变化，其他源码和配置必须保持；整理之后仍执行回读和严格编译，不把源文件任意变化设成可接受。

已在两个真实 H3U 工程中尝试所有登记的 IL 块，并在两个工程中均取得通过上述验收的转换。覆盖串并联、边沿、SET/RST、定时器等现有指令。部分块会被原厂重排 `MPS/MRD/MPP`，不符合逐指令回读一致，工具明确拒绝且不发布工程包。比较只忽略空行和指令名后的分隔空白；没有声称能还原任意 IL 或原始图形布局。

## 全局符号表：新增、修改、中文已通过

使用 Global.dll 的 `GetGVTList/GetAt` 读取，`SetName/SetAddress/SetComment` 修改，`Add` 新增，再由 `SaveGVTTable` 保存。没有自行拼接私有二进制格式，也没有用字符串扫描冒充符号表解析。

实际测试了中文名称、多行中文注释、新增行、修改已有行和重开子进程后的完整回读。修改前后清缓存编译的机器码相同，非派生输入文件中只有 `VarList.gdt` 改变。故意改动其他配置的测试被拒绝。

当前范围是全局名称、直接地址和注释；不支持删除、局部符号、结构化配置或会改变机器码的符号重映射。每次调用仍执行哈希、回读、配置和编译检查。

## 完整 H3U 运行仿真：未打通

在本机安装中找到了 `Simulator/h5u_daemon.exe` 和 `Simulator_V2R1`，复制后能脱离 GUI 启动。其设备模板标识为 H5U，相关运行库中有 H5U/Easy 设备处理；H530Converter/STCompiler 存在 `STSimTemp` 仿真构建路径。没有找到已验证的 H3U 引擎或 H3U 程序装载路径。

探针曾在空程序下完成 Modbus 数据区写入和回读；这只能说明服务在运行。数据区与 PLC 软元件的映射、用户程序扫描、定时器、计数器和轴指令均未验证，因此不算运行仿真。探测进程已停止；产品不提供这个启动接口。

本机帮助和设备模板支持 H5U/Easy 方向的判断，但缺少 H3U 字样不是“不可能支持”的证明。要继续实现 H3U 完整仿真，仍需确认兼容的执行引擎、仿真目标编译产物以及装载和扫描接口。不能用小范围 IL 解释器代替完整原厂仿真。

进一步对 H3U `CreateCompiler` 的选项 0、1、2、3 做了独立副本探针：0 只生成块缓存，1 未产生新文件，3 返回“开始反编译/反编译成功”，2 生成正常 H3U 程序且与基准机器码相同。这四个实测取值均未生成仿真引擎所需的 ELF/`.o` 等目标产物。选项 3 是仿真编译的猜测不成立；这也不等于排除尚未调查的其他接口。
